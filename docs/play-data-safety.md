Play Console →「ポリシー」→「アプリのコンテンツ」→「データ セーフティ」で聞かれる内容の回答案。
2026-10-02 に、アプリの実装（`src/app/api/`・画面・`supabase/migrations`・Android のマニフェストと AAB）と突き合わせて作り直した。
**提出前に、実装と食い違いがないか必ず確かめ直すこと**（事実と違う申告は、アプリの削除の対象になる）。

- 外部の会社（Anthropic・Supabase・Vercel・RevenueCat・Resend）は、どれも当方の依頼でデータを扱う**サービス プロバイダ**なので、「共有」には当たらない。すべて**共有なし**で申告する。
- プライバシーポリシー（`src/app/privacy/page.tsx`。2026-10-02 更新）も、これらを「第三者提供」ではなく「**業務の委託**」として書いている。申告とポリシーの書き方をそろえること。
- 外国の会社へ渡す根拠（個人情報保護法28条）は、**5社とも**各社の利用規約に組み込まれた DPA による基準適合体制（ポリシーの「5.」）。Anthropic も登録時の同意を根拠にしない（2026-10-02 より前の同意文には国名・制度・措置の情報がなく、同意もサーバーに保存していないため。経緯は `privacy/page.tsx` 冒頭のコメント）。登録時の同意は App Store の審査のために「あわせて」いただくもの。
- OpenAI はどこからも呼んでいない（コード・依存・環境変数のどれにもない）。申告にもポリシーにも書かない。

### アカウント作成の説明欄に貼る文（案）

> お名前を入力して登録します。パスワードやメールアドレスは使わず、アプリが端末の中で作るランダムなIDでアカウントを見分けます。機種変更のときは、アプリが発行する引継ぎコードで移します。

- 登録画面の欄は「お名前 *」で、入力例は「例: 山田太郎」（`src/app/page.tsx` の登録画面）。ニックネームでよいと書いているのはプライバシーポリシーだけなので、説明欄には「ニックネーム」と書かない。
- 引継ぎコードは8文字・1時間で失効・1回限り。ただし審査担当者用のコード（`reusable`）は使っても消えない（`src/app/api/transfer/restore/route.ts:46-55`）。

## 収集していないもの

| データ | 理由 |
|---|---|
| 正確な位置情報 | 位置の権限も Geolocation の呼び出しもない。写真は canvas で描き直すので EXIF の位置は付かない |
| 動画 | 姿勢チェックのカメラ映像は端末内の MediaPipe で使うだけ。送るのは保存を押したときの静止画1枚 |
| ユーザーの支払い情報 | Google Play の課金システムが直接扱い、アプリは触れない |
| 音声録音 | マイクを使っていない（RECORD_AUDIO なし）。撮影ガイドの声は用意した mp3 を流すだけ |
| クラッシュログ | Firebase・Sentry・Analytics なし。RevenueCat の診断送信も有効にしていない |
| 広告 ID | 上のとおり |
| Health Connect / HealthKit | Android には入っていない。iOS の HealthKit も「準備中」で、値をサーバーへ送らない |
| 連絡先・カレンダー・SMS・ファイル・閲覧履歴・インストール済みアプリ・電話番号・住所など | 扱っていない。通知は端末内のローカル通知だけで、FCM のトークンも集めていない |

申告の対象外としたもの：RevenueCat SDK が通信のヘッダーで送る機種名・OS・言語・アプリのバージョンなど（識別子ではなく、RevenueCat 公式の指針も対象にしていない）と、引継ぎコード（ID は「ユーザー ID」「デバイスまたはその他の ID」で申告済み）。

## 決めること（提出前）

1. **アカウントを削除せずにデータの一部を削除できるか**：調査の申告案は「いいえ」だったが、サポートの FAQ（`src/app/support/page.tsx` の「過去の会話を削除したい」「記録を編集・削除したい」）と、プライバシーポリシーの「10. ご本人からのご請求」は、チャットや食事の記録の一部だけを消す依頼をフォームで受けると書いている。家族グループからの脱退・解散でも、アカウントを残したまま家族のデータが消える。そのため、(a)「はい」にして、受けたら手作業で消す手順を決める（ポリシーの今の書き方と合う）か、(b) FAQ とポリシーのその案内を消してから「いいえ」にするか、どちらかに決めること。
2. **購入履歴の必須/任意**：RevenueCat の指針に合わせて「必須」にしているが、コードの上では、料金プラン画面を開いた人と購入した人だけから集める。正確さを優先するなら「任意」にしてもよい（どちらでも申告漏れにはならない）。

## 健康アプリとしての注意

- 健康情報を扱うので、Play の「センシティブなデータ」に当たる。プライバシーポリシーに健康データの扱いが書いてあるか（書いてある）を審査で見られる。
- 「医療アプリ」ではなく、セルフケアのアプリとして申告する方針は変えないこと（利用規約・アプリ内の表示・プライバシーポリシーの「13. 健康情報に関する重要なお知らせ」と食い違わないように）。
